# 云端学习交接与启动说明

## 学习背景

目标是学习 hcomm 整个项目，当前阶段重点理解 A2/910B 每个集合通信算子如何选择算法：为什么选它，何时切换，切换条件是什么。当前没有 NPU 开发环境，采用静态源码学习。

完整代码来自 9.1.0 的固定上游提交；来源和打包差异见 [source_provenance.json](source_provenance.json)。这是一份学习快照，不包含上游其他分支或完整 Git 历史。机型范围是分析阶段的约束，不意味着其他设备源码已被删掉。

已有成果见 [学习手册](README.md)：公共配置/拓扑/能力判断、15 个传统注册命令的选择条件、执行器内部模板、边界场景、源码证据和哈希基线。资料完成不代表学习者已经掌握；还没有逐课记录学习进度。

## 后续阅读顺序

1. 公共机制：明确 rank、server、module、聚合组、运行模式、CCL 容量和确定性。
2. AllGather：从实际 `SelectAlg` 跟到 910B 分支，以一个具体场景推导最终执行器。
3. AllReduce/ReduceScatter：加入归约能力、AIV、确定性和自动 level1 模型。
4. Broadcast/Reduce/Scatter/Barrier/点对点：辨认没有自动 V2 或只有固定执行器的路径。
5. V/AlltoAll：理解 counts/displs、矩阵容量、capture 与优先路径。
6. 内部模板：跟踪每轮大小、NHR oneshot、NB binary 和分层通信。

可直接从当前疑问开始，不要求机械按顺序学完。

## 已知限制

- 没有运行 CANN/HCCL 测试或 NPU 实验，不能给出真实性能排序。
- `BroadCast4pRingExecutor` 的字符串缺少同名注册；普通 A2 拓扑初始化未证明会生成该候选拓扑。
- 部分候选由共享代码或其他设备分支产生，95 个候选清单不等于 95 个已证明支持的 A2 执行器。
- 文档与源码可能在后续提交中改变；问答时核对当前源码和上游基线。
- Windows 本地路径已转换为相对链接与 `#L行号`。GitHub 可跳到源码行；本地 Markdown 查看器不一定支持行号锚点，仍可按标注行号读取。

## 在 Codex 云端开始

在账号界面授权访问 `zznotlazy/hcomm-9.1.0-learning`，选择这个仓库并确认检出的分支为 `9.1.0`。这是源码问答环境，初始阶段不需要安装 CANN，也不要求 GPU/NPU。若界面没有分支选择，明确让任务检查当前分支和 `source_provenance.json` 中的基线，不使用另一个版本讲解。

新建任务可复制以下提示词：

```text
我在学习这个仓库中的 hcomm 9.1.0 源码，当前重点是 Ascend A2/910B
集合通信算法选择与切换条件，没有 NPU/CANN 运行环境。
请先阅读根目录 AGENTS.md，以及
docs/zh/learning/a2_algorithm_selection/README.md 和 CLOUD_LEARNING.md。
请用中文教学，结合真实源码给出相对路径、函数名和行号，区分源码事实、
机制推断与未验证结论。默认只读讲解，不修改源码，不自动安装 CANN。
不要假设已有其他聊天记忆。
我现在的问题是：AllGatherOperator::SelectAlg 怎样一步步选择到 A2 执行器？
```

之后尽量继续同一个云端任务。换任务时提供学习说明与进度摘要；共享仓库本身不会合并独立对话。重要学习结论可在你明确要求时提交到 Git，而不是只保存在聊天里。
