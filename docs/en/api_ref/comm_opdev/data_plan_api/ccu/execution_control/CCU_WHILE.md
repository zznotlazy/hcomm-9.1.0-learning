## Description

`CCU_WHILE` is a preprocessor macro that carries two semantics, which are automatically distinguished by whether a `CCU_DO` precedes it:

1. Standalone while loop: `CCU_WHILE(condExpr) { body }` - When no `CCU_DO` precedes `CCU_WHILE`, it acts as a normal while loop: the condition is evaluated first in each iteration, and the body is executed only when the condition is met.
2. do-while termination: `CCU_DO { body } CCU_WHILE(condExpr);` - When a `CCU_DO` precedes `CCU_WHILE`, it acts as the termination of a do-while loop: the condition is evaluated after the body is executed, and if the condition is met, it returns to the beginning of the loop.

The two semantics are completely transparent to users, and the syntax is consistent with the C++ standard while/do-while. For the do-while usage, see [CCU_DO](CCU_DO.md).

## Macro Syntax

```cpp
// Semantics 1: standalone while loop
CCU_WHILE(condExpr) {
    // body
}

// Semantics 2: do-while termination (must immediately follow CCU_DO { })
CCU_DO {
    // body
} CCU_WHILE(condExpr);
```

## Parameters

| Parameter | Description |
| --- | --- |
| condExpr | Conditional expression of the type `AscendC::ccu::CondExpr`. It is generated by `operator==(uint64_t)` or `operator!=(uint64_t)` of `ccu::Variable`. The condition is evaluated by the CCU hardware at runtime. |

For the definition and generation of `CondExpr`, see [CCU_IF](CCU_IF.md#parameters).

## Return Value

`CCU_WHILE` is a preprocessor macro and does not return [CcuResult](../../../datatype_definition/CcuResult.md) by itself. If an internal error occurs after macro expansion (such as duplicate labels or an invalid handle), `CCU_E_PARA`/`CCU_E_NOT_FOUND` may be generated. In this case, the macro does not throw an exception or block registration: on failure, the body is skipped, but registration still succeeds. Errors are not fed back through the return value, so pay attention to this during debugging.

## Constraints

- `CCU_WHILE(condExpr)` must be immediately followed by a loop code block enclosed in {}.
- For Ascend 950PR/Ascend 950DT, the current `condExpr` of `CCU_WHILE` supports only the == and != comparison modes.
- The immediate value (`imm`) compared in `condExpr` must be of the `uint64_t` type.
- When used as a standalone while loop, `CCU_WHILE` can be nested, and an inner `CCU_WHILE` can be used inside the body of an outer `CCU_WHILE`.
- `CCU_WHILE` (standalone while) can be nested in combination with `CCU_IF`.
- `CCU_WHILE` (regardless of its semantics) cannot be used inside the body lambda of `ccu::Loop`, because software branches/loops are not supported inside a hardware loop body.

## Example

```cpp
using namespace AscendC::ccu;

// Scenario: standalone while loop that loops the counter 10 times
CcuResult MyKernel(CcuKernelArg arg) {
    Variable counter, limit, one;
    counter = 0;
    limit = 10;
    one = 1;

    CCU_WHILE(counter != limit) {
        // Loop body
        counter = counter + one;
    }

    return CCU_SUCCESS;
}
```
